# Xiangqi Arena 设计文档

日期：2026-10-08

## 1. 目标与定位

一个本地运行的中国象棋对弈平台，同时服务两类用户：

- **人类玩家/观众**：通过浏览器点击棋盘走子；观战两个 Agent 对弈，实时看到棋盘与双方的思考流。
- **Agent Harness**：通过 CLI / HTTP API 对弈，全程纯文本交互（FEN + ASCII 棋盘），不依赖图片，节省 token。

三种对弈模式：人 vs Agent、Agent vs Agent、人 vs 人；观战模式是重点场景。

### 成功标准

1. 两个本地 Agent Harness 能通过 `xq` CLI 完成一整局合规对弈，人可在浏览器实时观战并看到双方思考流。
2. 人可以在浏览器点击棋盘与 Agent 或 Pikafish 引擎对弈。
3. 非法走法、违反轮流走子、超时均被服务端拒绝或判负。
4. Agent 走棋必须经"预览 → 确认提交"两阶段，预览效果以文字明确描述。
5. 对局结束前一个 Agent 无法通过服务器协议获取对方思考。

### 明确不做（本期范围外）

- 账号系统（座位 token 即身份）
- 联机对战/远程匹配（仅本机或局域网观战）
- 前端框架与构建链
- 移动端 App

## 2. 架构总览

本地服务器是唯一裁判与状态真相源，三类客户端都连接它：

```
┌─────────────┐   HTTP/SSE       ┌──────────────────────────┐
│  浏览器 UI   │ ◄──────────────► │                          │
│ (走子/观战)  │                  │  xq-server (FastAPI)      │
├─────────────┤                  │   ├─ 规则核心(自研 Python) │
│ Agent A CLI  │ ◄─── HTTP ─────► │   ├─ 对局管理/两阶段提交   │
├─────────────┤                  │   ├─ 座位令牌/信息隔离     │
│ Agent B CLI  │ ◄─── HTTP ─────► │   ├─ 双钟计时            │

                                    Pikafish 引擎进程
                                    (AI 对手 / 局面分析)
```

## 3. 规则核心（独立 Python 包，可单独测试）

- 棋盘表示：9 路 × 10 线共 90 个交叉点；FEN 读写（初始局面 `rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1`）。
- 走法校验：车马炮兵仕相帅完整规则，含蹩马腿、塞象眼、仕/帅不出九宫、兵过河、白脸将（将帅照面）。
- 将军/应将/将死/困毙判定；长打禁着（长将/长捉判负）本期不实现，和棋仅靠自然限着与协议和棋（见 §6）。
- 记谱双轨：
  - **ICCS 坐标记谱**（`h2e2`）——Agent 接口与内部表示。
  - **中文记谱**（炮二平五）——UI 棋谱列表显示。二者由核心互转。
- **文本棋盘渲染**：ASCII 棋盘（带 a–i / 0–9 坐标刻度），`state` 接口随 FEN 一起返回，Agent 无需任何图片。

## 4. 对局协议

### 4.1 座位与令牌

- 建局时生成红/黑两个独立随机 token，分别交付两方（CLI 存入各自工作目录，`chmod 600`）。
- 服务端只接受"持有当前行棋方 token"的请求：从机制上保证一人一步、不能代对方走子。

### 4.2 两阶段提交（落棋确认）

1. `POST /games/{id}/move {move: "h2e2"}` → 校验合法性后返回**预览**，棋局不变：
   - 文字描述效果：`红炮 h2→e2，吃黑马` / `未吃子`
   - 走后 FEN、是否将军、剩余合法应对数
   - 一个 `pending_id`
2. Agent 核对预览符合预期 → `POST /games/{id}/commit {pending_id}` 落子；不符合 → `POST /games/{id}/cancel {pending_id}`。
3. pending 状态有有效期（默认 60 秒，且不超过当前剩余步时），过期自动作废，需重新 preview。preview 阶段**照常计时**（见 §6），防止用 preview/cancel 循环白嫖思考时间。

### 4.3 对局终局

将死/困毙判负；超时判负；认输（`xq resign`）；协议和棋（`xq offer-draw` / `accept-draw`，拒绝或不应答则继续）；自然限着和棋（默认连续 60 回合双方无吃子，可配置）。

## 5. CLI（`xq`）

```
xq serve [--port 8000]                        # 启动裁判服务器
xq new --red-name Kimi --black-name Claude \  # 建局，输出 game-id 与两个 token
       [--time 15m --step-time 3m --increment 10s]
xq join <game-id> --color red --token <tok>   # 入座（写入本地 seat 文件）
xq state                                      # FEN + ASCII 棋盘 + 是否轮到我 + 剩余局时/步时
xq legal-moves                                # 当前全部合法走法（ICCS 列表）
xq move h2e2 [--note "…"]                     # 预览这步的效果（可附思考）
xq commit / xq cancel                         # 确认或撤销 pending 走法
xq note "对方中路空虚，我准备…"                 # 思考流，仅观战者可见
xq wait [--timeout 300]                       # 阻塞等待轮到自己（长轮询）
xq resign / xq offer-draw / xq accept-draw
xq replay <game-id>                           # 本地复盘棋谱
```

Agent 对弈循环即一个 shell 循环：`wait → state → 思考(note) → move → 核对预览 → commit`。交付物包含一段现成的 prompt 模板（含规则要点、命令用法、纪律要求），喂给 Harness 即可开赛。

## 6. 时限模块（双钟制）

参考《象棋竞赛规则（2020）》及正式网络赛事惯例（局时 15 分钟 + 步时 3 分钟 + 每步加 10 秒）：

- **局时**：每方总时间池，耗尽判负。
- **步时**：单步思考上限，超时直接判负。
- **加秒**：每 commit 一步，该方时间池加回 N 秒。
- 默认值：`局时 15 分钟，步时 3 分钟，加秒 10 秒`（Agent 对局场景），全部可在 `xq new` 时配置。
- **服务端权威计时**：上一步 commit 落子即为下一方开始走表，commit 停表；preview 阶段照常走表。超时由服务端自动判负并广播。
- `state` 接口与观战页实时显示双方剩余时间。

## 7. 防作弊分层设计

诚实前提：同一台电脑、同一用户账号下无法做到绝对防偷看。按泄漏路径分层：

| 泄漏路径 | 对策 | 层级 |
|---|---|---|
| 服务器协议 | 对方思考永不返回给 Agent；token 鉴权；访问日志（谁、何时、请求了什么） | 默认 |
| 读对方本地文件（trajectory / session / token） | seat token 与服务器数据目录 `chmod 600`；可选 `sandbox-exec` profile：每个 Harness 只允许读写自己的工作目录 + 访问 `127.0.0.1:<port>`，提供现成启动脚本 | 默认 + 可选加固 |
| 截屏/读屏观战浏览器 | 不授予运行 Agent 的终端 App「屏幕录制/辅助功能」TCC 权限（截图将被系统拒绝或黑屏）；或观战页绑局域网、用手机观看 | 文档指引 |
| 事后作弊 | **赛后审计工具**：对比双方 trajectory 与对方 note 原文，出现逐字撞车即标记偷看嫌疑（类比正式比赛赛后棋谱查软） | 默认 |

## 8. Web 界面（服务器自带，无构建步骤）

- **对弈页**：SVG 棋盘点击走子（选中→点目标点→弹预览→确认，与服务端两阶段提交一致）。人类座位 token 存于浏览器会话。
- **观战页**：
  - 棋盘居中，**左栏红方思考流、右栏黑方思考流**，气泡按回合标注，自动滚动。
  - 思考数据流：Agent `xq note` → 服务器记录（含回合数、颜色、时间戳，写入棋谱）→ SSE 广播给观战页（**绝不发给对手**）→ 浏览器按颜色入对应侧栏。
  - 无 note 时侧栏显示中文记谱 + 可选 Pikafish 局面评分。
- **棋盘朝向**：
  - 人机对战（人执红）：传统朝向，楚河汉界横向，红方在底。
  - 观战 Agent vs Agent：旋转 90°，楚河汉界**竖向**，红方在左、黑方在右，与左右思考侧栏方位一致。
  - 实现：渲染函数接收 `orientation` 参数做坐标映射，两种朝向共用一套绘制代码，棋子文字随朝向旋转保持正向可读。
- **棋子资源层**：第一版用 Unicode 汉字棋子绘于 SVG；渲染从 `assets/pieces/` 读取资源，后续将生图 AI 产出的棋子图片放入该目录即可无缝替换，代码不改。
- 公平模式开关：人机对战中可关闭对方思考侧栏。

## 9. Pikafish 集成（可选模块）

- 编译官方 Pikafish（C++，macOS 支持），服务器通过 UCI 协议以子进程方式驱动。
- 用途：作为 AI 对手入座（占用一个座位，走子由引擎产生）；局面分析（观战页显示评分）。
- 职责边界：Pikafish 只当"选手/分析员"，裁判、两阶段提交、隔离逻辑全部由自研核心负责。

## 10. 持久化与复盘

- 每局写入 `data/games/<game-id>.jsonl`：每手含 ICCS、中文记谱、走后 FEN、用时、note。
- `xq replay` 与 Web 复盘页按手回放。

## 11. 测试

- pytest 覆盖规则核心：每种棋子合法/非法走法、蹩马腿/塞象眼、白脸将、将军/将死、自然限着计数、FEN 往返。
- 协议测试：轮流走子强制、token 鉴权、两阶段提交状态机、超时判负、思考隔离（对手请求 note 被拒绝）。
- 端到端：两个模拟 Agent 进程通过 CLI 打完一局（Pikafish 或随机合法走法驱动）。
